<objective>
Customer-facing UI for viewing all orders and inspecting any one of them. Reverse-chronological list with 4 filter chips; detail screen with per-seller collapsible sections and a vertical 4-status stepper component shared with the seller plan. All reads go through Room via OrderRepository (single source of truth); sync happens on screen open + pull-to-refresh + FCM event (via SyncBus from 06-04).

Purpose: Closes ORDR-01..ORDR-04 by giving customers the visibility CONTEXT D4 promises. The reusable Stepper + Badge components built here are also consumed by Plan 06-03 (seller UI), so naming, package placement, and prop shapes must be reuse-friendly. SyncBus collection here is what makes CONTEXT D4 trigger c (FCM-driven sync) observable to the customer.

Output: Two screens + ViewModels + States/Actions; three core components (Badge, Stepper, TrackingChip); type-safe routes; Koin wiring; profile menu entry; ViewModel unit tests (including SyncBus emission triggers sync) + Compose UI tests.

Wave note: depends_on includes 06-04 because the SyncBus + SyncEvent contract is owned by 06-04. 06-02 collects from it. This pushes 06-02 to Wave 3 (06-04 ships in Wave 2 alongside 06-03).
</objective>
