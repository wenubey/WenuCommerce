# Phase 7 — UI Design Contract: Reviews & Ratings

> Visual and interaction contract for Phase 7 frontend work (plans 07-02 and 07-03).
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Material 3 via Jetpack Compose) |
| Preset | not applicable |

## Spacing Scale

Declared values (multiples of 4 only, in dp):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon-to-text gaps, dot indicator padding, star-to-count gap |
| sm | 8dp | Intra-card section spacing, avatar-to-name gap, badge padding vertical |
| md | 16dp | Card content padding, screen horizontal padding, form field spacing |
| lg | 24dp | Section separator spacing, aggregate block vertical padding |
| xl | 32dp | Bottom scroll spacer, form submit button top margin |
| 2xl | 48dp | Empty state illustration bottom margin |
| 3xl | 64dp | Not used in this phase |

Exceptions:
- Star icon touch target: 44dp minimum (accessibility — each star in the interactive 1-5 selector uses a 44dp-wide touch area even though the visual icon is 32dp).
- Avatar circle: 32dp diameter (matches existing `ReviewCard` avatar; not a spacing value).
- Helpful `IconButton`: 32dp size (matches existing implementation; below 44dp minimum but inherits parent card tap area — acceptable for secondary action).

All roles map to existing Material 3 type scale. No custom sizes are introduced.

| Role | M3 Token | Size (sp) | Weight | Line Height |

| Aggregate count ("128 reviews") | `bodyMedium` | 14sp | Normal (400) | 20sp |

## Color

All color values are resolved at runtime from `MaterialTheme.colorScheme` (dynamic color on API 31+; static Purple-family fallback on older devices). No hardcoded hex values except the star amber.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` / `colorScheme.background` | Screen background, LazyColumn background |
| Secondary (30%) | `colorScheme.surfaceVariant` | Review cards container, form card background, avatar fallback background |
| Accent (10%) | `colorScheme.primary` | Star fill color for interactive selector (selected stars), "Submit Review" / "Update Review" button container, section heading color on write-review affordance link |
| Star amber (fixed) | `Color(0xFFFFC107)` | Read-only filled stars in review cards and aggregate display (matches existing `ReviewCard` and `CustomerProductDetailScreen`) |
| Verified Purchase badge container | `colorScheme.primaryContainer` | Badge background |
| Verified Purchase badge content | `colorScheme.onPrimaryContainer` | Badge text |
| Destructive / error | `colorScheme.error` / `colorScheme.errorContainer` | Submission error snackbar, validation error text |
| Disabled / muted | `colorScheme.onSurfaceVariant` | Outlined stars, relative date, count text, not-eligible explanation |

Accent (`colorScheme.primary`) is reserved for:
1. Interactive star selector — filled stars at or below current selection.
2. "Submit Review" and "Update Review" filled `Button`.
3. "Write a Review" `TextButton` label on product detail (the entry affordance).

The amber `Color(0xFFFFC107)` is only for display-only (read-only) stars. Interactive stars use `primary` for selected and `onSurfaceVariant` for unselected to meet contrast requirements.

## Component Inventory

### C-01: StarRatingDisplay (read-only)

Reuse the pattern already in `CustomerProductDetailScreen.kt` and `CustomerHomeScreen.kt`. Exact spec:

- 5 icons in a `Row`, horizontal spacing 2dp.
- Icon: `Icons.Filled.Star` (filled, amber `0xFFFFC107`) for `index < rating`, `Icons.Outlined.Star` (outlined, `colorScheme.onSurfaceVariant`) otherwise.
- Size variants:
  - **Large** (aggregate header): 20dp icons.
  - **Medium** (review card): 14dp icons (matches existing `ReviewCard`).
  - **Small** (product card compact row): 14dp icon, single star only (one icon + count text).
- Content description: `"$rating out of 5 stars"` on the `Row` container; individual icons set `contentDescription = null`.

### C-02: StarRatingSelector (interactive, write form)

New composable `StarRatingSelector` in `app/.../customer/customer_reviews/`.

- 5 `IconButton` composables in a `Row`, each 44dp wide × 44dp tall touch target.
- Visual icon size: 32dp.
- Icon: `Icons.Filled.Star` (`colorScheme.primary`) for `index < selectedRating`, `Icons.Outlined.Star` (`colorScheme.onSurfaceVariant`) otherwise.
- On tap of star N: emit `onRatingSelected(N + 1)` (1-indexed).
- Content description per button: `"Rate $starNumber out of 5 stars"` (e.g. "Rate 3 out of 5 stars").
- Required field — the Submit button is disabled while `selectedRating == 0`.
- No animation. Immediate icon swap on selection.

### C-03: VerifiedPurchaseBadge

New composable `VerifiedPurchaseBadge` in `core/components/`, modeled on `OrderStatusBadge`:

```
Text(
    text = "Verified Purchase",
    style = MaterialTheme.typography.labelMedium,
    color = colorScheme.onPrimaryContainer,
    modifier = Modifier
        .background(colorScheme.primaryContainer, RoundedCornerShape(8.dp))
        .padding(horizontal = 10.dp, vertical = 4.dp)
)
```

- Only rendered when `review.isVerifiedPurchase == true`.
- Content description: `"Verified Purchase"` (the text is also visible so no separate talkback string needed beyond the text itself).
- Placed in the review card header row, trailing after the reviewer name/stars column.

### C-04: AggregateRatingHeader

New composable surfaced as a `LazyColumn` item above the review list on product detail.

Layout (vertical stack, `md` = 16dp padding horizontal):

```
Row {
    Column {                            // left: large numeric + stars
        Text("4.3", headlineSmall, bold)
        StarRatingDisplay(rating = 4, size = Large)   // floor of average
        Text("128 reviews", bodyMedium, onSurfaceVariant)
    }
    Spacer(weight = 1f)
    // right column reserved for future rating histogram — empty in Phase 7
}
```

- If `reviewCount == 0`: render `Text("No ratings yet", bodyMedium, onSurfaceVariant)` instead of the numeric row.
- The average is formatted as `"%.1f".format(ratingAverage)`.
- Star display uses floor of `ratingAverage` for filled count (existing pattern).

### C-05: ReviewSortToggle

Material 3 `SegmentedButton` row (two segments):

- Segment 1: "Most recent" — default selected.
- Segment 2: "Highest rated".
- Uses `SingleChoiceSegmentedButtonRow` from `androidx.compose.material3`.
- On segment tap: emit `onSortChanged(ReviewSortOrder)` where `ReviewSortOrder` is a new domain enum `{ MOST_RECENT, HIGHEST_RATED }`.
- Content description on each button: `"Sort reviews by most recent"` / `"Sort reviews by highest rated"`.
- Placed as a `LazyColumn` item between `AggregateRatingHeader` and the review list.

### C-06: ReviewCard (enhanced from existing)

The existing private `ReviewCard` in `CustomerProductDetailScreen.kt` is extracted to `core/components/ReviewCard.kt` and extended:

New fields added to layout:
1. **VerifiedPurchaseBadge** — placed in the header Row, after the reviewer name/stars column, trailing aligned.
2. **Relative date** — `Text(relativeDate, bodySmall, onSurfaceVariant)` trailing in the header Row.
3. **Helpful button** — existing `IconButton` is replaced with a `TextButton` labeled `"Helpful (N)"`:
   - Normal state: `TextButton` with `Icons.Outlined.ThumbUp` (16dp) + label `"Helpful ($helpfulCount)"`.
   - After vote (local state `hasVoted = true`): button is disabled (`enabled = false`), tint shifts to `colorScheme.onSurfaceVariant`. Label stays `"Helpful ($helpfulCount)"` (count reflects server update via Flow).
   - Content description: `"Mark review as helpful, currently $helpfulCount people found this helpful"`.
4. **Review title** — already present; no change needed.

Full card layout (top-to-bottom inside `Card` with `md` padding):

```
Row(verticalAlignment = CenterVertically) {
    Avatar (32dp circle)
    Spacer(sm)
    Column {
        Text(reviewerName, labelMedium)
        StarRatingDisplay(rating, Medium)
    }
    Spacer(weight = 1f)
    VerifiedPurchaseBadge (conditional)
    Spacer(xs)
    Text(relativeDate, bodySmall, onSurfaceVariant)
}
Spacer(sm)
Text(title, titleSmall, medium weight)   // conditional, if title not blank
Spacer(xs)
Text(body, bodyMedium)
Spacer(sm)
Row {
    HelpfulButton (TextButton)
}
```

Card elevation: 1dp (matches existing).
Card container color: default `colorScheme.surface`.

### C-07: WriteReviewForm

New full-screen composable `WriteReviewScreen` (`customer/customer_reviews/WriteReviewScreen.kt`).

Surfaced as a bottom sheet or separate navigation destination (decision: **separate navigation destination** — consistent with the existing app pattern of full-screen forms like `SellerProductCreateScreen`).

Layout (LazyColumn with `md` horizontal padding):

```
TopAppBar("Write a Review")       // back navigation
Spacer(lg)
StarRatingSelector                // C-02 — required
Spacer(md)
OutlinedTextField(                // optional title
    label = "Title",
    placeholder = "Summarise your experience",
    singleLine = true,
    maxLines = 1,
)
Spacer(md)
OutlinedTextField(                // optional body
    label = "Review",
    placeholder = "What did you like or dislike?",
    minLines = 4,
    maxLines = 8,
    modifier = Modifier.fillMaxWidth(),
)
Text("${body.length}/1000", bodySmall, onSurfaceVariant, align = End)
Spacer(xl)
Button(                           // primary CTA
    text = if (isEditMode) "Update Review" else "Submit Review",
    enabled = selectedRating > 0 && !isSubmitting,
    modifier = Modifier.fillMaxWidth(),
)
```

- Title field: max 100 characters. Character counter not shown for title (short enough to self-limit).
- Body field: max 1000 characters. Character counter displayed below field: `"${body.length}/1000"`.
- When `isSubmitting == true`: Button shows `CircularProgressIndicator(size = 16dp, color = onPrimary, strokeWidth = 2dp)` inside the button; same pattern as existing `CartActionSection`.
- Pre-filled mode (D-05, edit): All three fields pre-populated from existing review. Button label is "Update Review". TopAppBar title is "Edit Review".

### C-08: WriteReviewAffordance (entry point on product detail)

Placed as a `LazyColumn` item between the tags section and the reviews section divider.

Gate rules (D-07):
- `isEligibleToReview == true` AND `existingReview == null`: Show `TextButton("Write a Review", primary)` + `Icon(Icons.Default.RateReview, 20dp)`.
- `isEligibleToReview == true` AND `existingReview != null`: Show `TextButton("Edit Your Review", primary)` + the existing review's star display in a compact row.
- `isEligibleToReview == false`: Show nothing. (The Cloud Function is the authority; UI gate is defence-in-depth per D-07.)
- `isCheckingEligibility == true`: Show a `LinearProgressIndicator(modifier = Modifier.fillMaxWidth().height(2dp))` in place of the affordance.

### C-09: ProductCardRatingRow (REVW-07)

Applied inside the existing `CustomerProductCard` composable (already partially implemented in `CustomerHomeScreen.kt`).

Current code:
```kotlin
if (product.reviewCount > 0) {
    Row { Icon(Star, 14dp, amber) + Text("%.1f (%d)".format(avg, count), bodySmall) }
}
```

**No change needed to the visual design** — this is already correct. The Phase 7 executor must ensure `product.averageRating` and `product.reviewCount` are populated from the denormalised product doc fields (`ratingAverage` / `ratingCount` per D-03).

Content description added by Phase 7 executor on the Row: `"Rated ${"%.1f".format(avg)} out of 5, $count reviews"`.

When `product.reviewCount == 0`: render nothing (existing behaviour — correct).

## Interaction Contracts

### Star Selector (write form)
- Tap star N: sets `selectedRating = N` immediately (optimistic, no network call).
- No long-press, no swipe gesture.
- Keyboard: each star button is individually focusable; Enter/D-pad activates the tap.

### Sort Toggle
- Tap "Highest rated": re-sorts the in-memory list descending by `rating`, ties broken by `createdAt` descending. No network call — sort is client-side on the observed Flow result.
- Toggle is stateless in the ViewModel UI layer (no persistence across screen exits).

### Helpful Button
- Single tap: fires `markReviewHelpful(reviewId)` via ViewModel action.
- Local state `helpfulVotedIds: Set<String>` in ViewModel tracks which review IDs the current session has voted on. Button becomes disabled immediately on tap (optimistic disable).
- No undo. No double-vote prevention UI beyond the disabled state (server enforces per D-04).
- After server response, the review's `helpfulCount` updates via the Firestore Flow and the displayed count reflects the real value.

### Write Review Navigation
- Affordance taps navigate to `WriteReviewScreen` via type-safe route `CustomerRoutes.WriteReview(productId: String, existingReviewId: String? = null)`.
- On back press or TopAppBar back arrow: navigate up without saving.
- On submit success: navigate up + `ProductDetailViewModel` re-observes the reviews Flow (count and list update automatically via Firestore listener).

## Accessibility Contract

| Surface | Requirement |
|---------|-------------|
| `StarRatingDisplay` container Row | `contentDescription = "$rating out of 5 stars"` |
| Individual `StarRatingDisplay` icons | `contentDescription = null` (parent Row describes the group) |
| `StarRatingSelector` each `IconButton` | `contentDescription = "Rate $n out of 5 stars"` where n = 1..5 |
| `StarRatingSelector` selected star | No additional description; selection communicated by `contentDescription` on press |
| `VerifiedPurchaseBadge` | Text is visible; no additional contentDescription needed |
| `ProductCardRatingRow` Row | `contentDescription = "Rated ${"%.1f".format(avg)} out of 5, $count reviews"` |
| Helpful `TextButton` | `contentDescription = "Mark review as helpful, $helpfulCount people found this helpful"` |
| Helpful `TextButton` disabled | `contentDescription = "You already marked this review as helpful"` |
| Review date | `contentDescription = "Reviewed $formattedAbsoluteDate"` (ISO date on talkback even though display shows relative) |

Minimum touch targets: 44dp for interactive stars, standard 48dp for TextButton, 32dp for Helpful IconButton (secondary action inside a card — acceptable per Material 3 guidelines for secondary card actions).
