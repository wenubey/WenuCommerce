<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Android client → Firestore notifications subcollection | Untrusted client can attempt to read/write notification docs |
| Cloud Function (Admin SDK) → notifications subcollection | Trusted server writer (bypasses rules) — created in plan 08-02 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | client writing fake notification docs | mitigate | firestore.rules `allow create, delete: if false` on notifications/{uid}/items (Task 3) — only Admin SDK writes |
| T-08-02 | Information Disclosure | reading another user's notifications | mitigate | `allow read: if request.auth.uid == userId` owner scope (Task 3) |
| T-08-03 | Elevation of Privilege | client mutating non-read fields (e.g. body/title/deep-link) via update | mitigate | `diff(...).affectedKeys().hasOnly(['read'])` restricts client update to the read flag only (Task 3) |
| T-08-04 | Denial of Service | listener started with blank uid → PERMISSION_DENIED spam | mitigate | gate startListener on non-blank userId; start only from authStateListener non-null branch (Task 2, RESEARCH §Pitfall 4) |
| T-08-SC | Tampering | npm/gradle installs | accept | no new packages this plan (RESEARCH §Package Legitimacy Audit: zero new deps) |
</threat_model>
