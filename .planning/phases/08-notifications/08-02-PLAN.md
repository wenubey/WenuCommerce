the foreground client-write path in 08-03 can dedup against the server doc (RESEARCH §Pitfall 5).

| Cloud Function → seller/customer FCM + notifications docs | Server-authoritative writer using Admin SDK |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05 | Spoofing | seller spoofs new_review FCM to another seller | mitigate | onNewReview is the only writer; clients cannot call FCM directly; recipient derived from product.sellerId server-side (Task 1) |
| T-08-06 | Information Disclosure | review notification routed to wrong seller | mitigate | seller resolved via `PRODUCTS/{productId}.sellerId` lookup, not client input (Task 1) |
| T-08-07 | Denial of Service | flood notifications subcollection | accept | trigger fires only on real Firestore review create (submitReview enforces one-per-customer-per-product in Phase 7); not a callable endpoint (RESEARCH §Security Domain) |
| T-08-08 | Tampering | trigger crash on missing fcmToken drops history | mitigate | notifications-doc write happens BEFORE and independent of FCM send; FCM failure is caught and logged, never thrown (Task 1/2) |
| T-08-SC | Tampering | npm installs | accept | no new packages (RESEARCH §Package Legitimacy Audit: zero new deps) |
</threat_model>
