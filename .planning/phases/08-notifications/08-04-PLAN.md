## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client mark-as-read write → Firestore notifications doc | Owner-scoped, read-flag-only (enforced by rules from 08-01) |
| System permission dialog → app | OS-controlled POST_NOTIFICATIONS grant/deny |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-12 | Elevation of Privilege | client marking another user's notification read | mitigate | markAsRead operates only on the auth user's own docs; Firestore rule (08-01) restricts update to owner + read field only |
| T-08-13 | Information Disclosure | history screen showing another user's notifications | mitigate | ViewModel queries observeNotifications(currentUser.uuid) only; Room rows are user-scoped and Firestore listener is per-uid (08-01) |
| T-08-14 | Annoyance/Abuse | permission dialog nagging on every launch | mitigate | DataStore notification_permission_requested gate + API 33 guard prevents re-prompt (Task 2, D-02, RESEARCH §Pitfall 6) |
| T-08-SC | Tampering | gradle installs | accept | no new packages; all libs already in libs.versions.toml (RESEARCH §Package Legitimacy Audit) |
</threat_model>
