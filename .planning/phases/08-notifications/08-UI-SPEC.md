## Spacing Scale

Declared values (multiples of 4 dp — matches 8-point grid at Compose dp):

| Token | Value | Usage in this phase                                      |
|-------|-------|----------------------------------------------------------|
| xs    | 4 dp  | Icon-to-text gaps, unread dot margin                     |
| sm    | 8 dp  | Compact spacing inside notification row (between lines)  |
| md    | 16 dp | Card internal padding, screen horizontal padding         |
| lg    | 24 dp | Empty-state icon bottom margin                           |
| xl    | 32 dp | Empty-state column padding (matches CustomerOrderHistoryScreen EmptyOrders pattern) |
| 2xl   | 48 dp | Not used in primary layouts this phase                   |
| 3xl   | 64 dp | Not used in primary layouts this phase                   |

Exceptions:
- Touch targets for notification row cards: minimum 48 dp tall (Android accessibility minimum).
- Type-icon size: 24 dp (matches existing `ProfileMenuItem` and `SettingsItem` icon sizing).
- Unread indicator dot: 8 dp diameter, 4 dp start margin before icon.

Source: Inferred from CustomerOrderHistoryScreen (16 dp card padding, 12 dp vertical gap, 32 dp empty state padding), CustomerProfileScreen (16 dp padding, 16 dp spacing).

## Typography

All roles use Material 3 typography tokens; the project does not override them beyond `bodyLarge`.
Sizes below are M3 defaults as shipped by Compose (not overridden in Type.kt).

| Role        | M3 Token          | Size  | Weight  | Line Height |
|-------------|-------------------|-------|---------|-------------|
| Notification title (unread) | `titleSmall` | 14 sp | SemiBold (600) | 20 sp |
| Notification title (read)   | `titleSmall` | 14 sp | Normal (400)   | 20 sp |
| Body snippet / subtitle     | `bodyMedium`  | 14 sp | Normal (400)   | 20 sp |
| Relative timestamp          | `bodySmall`   | 12 sp | Normal (400)   | 16 sp |
| Section / top-bar title     | `titleLarge`  | 22 sp | Normal (400)   | 28 sp |
| Dialog body                 | `bodyMedium`  | 14 sp | Normal (400)   | 20 sp |
| Dialog title                | `headlineSmall` | 24 sp | Normal (400) | 32 sp |

Rationale: mirrors the OrderRow pattern (`titleSmall` for ID, `bodyMedium` for secondary, `bodySmall` for date). Unread emphasis is weight change only — no size change — to maintain rhythm.

## Color

The project uses dynamic color (system-generated scheme on API 31+) with a fixed fallback.
All surface/accent values are M3 colorScheme tokens, not hardcoded hex.

| Role            | M3 Token                              | Specific usage in this phase                          |
|-----------------|---------------------------------------|-------------------------------------------------------|
| Dominant (60%)  | `colorScheme.background` / `.surface` | Screen backgrounds, Scaffold content area             |
| Secondary (30%) | `colorScheme.surfaceVariant`          | Notification row card container (unread tinted state) |
| Accent (10%)    | `colorScheme.primary`                 | Unread indicator dot, "Mark all read" TextButton, "Enable" dialog button, settings row icon tint |
| Error / destructive | `colorScheme.errorContainer` / `.onErrorContainer` | Not used in notification surfaces; reserved for future destructive notification actions |

Accent reserved for (explicit list):
1. Unread indicator dot (8 dp filled Circle, `colorScheme.primary`)
2. "Mark all read" action button text (`colorScheme.primary` TextButton)
3. "Enable" button in POST_NOTIFICATIONS rationale dialog (filled Button, `colorScheme.primary`)
4. Notification type-icon tint for `order_status` and `new_order` types (see type vocabulary)
5. "Enable Notifications" settings row icon tint (`colorScheme.primary`)

Unread row tinted background: `colorScheme.primaryContainer` at alpha 0.15 (achieved via
`Modifier.background(colorScheme.primaryContainer.copy(alpha = 0.15f))` on the Card container).
Read row background: default `Card` elevation surface (matches OrderRow).

## Surface Specifications

### 1. Notification History Screen (`NotificationHistoryScreen`)

**Route:** New screen reachable from Customer Profile tab and Seller Profile tab via a dedicated "Notifications" menu item (see Entry Point section).

**Scaffold structure:**
```
Scaffold(
  topBar = TopAppBar(title = "Notifications", navigationIcon = ArrowBack),
  snackbarHost = SnackbarHost,
  actions = [TextButton("Mark all read")] — visible only when unread items exist
)
```

**TopAppBar:**
- Title: "Notifications" (`titleLarge`)
- Navigation icon: `Icons.AutoMirrored.Filled.ArrowBack`, contentDescription = "Back"
- Action (conditional): `TextButton("Mark all read")` in `colorScheme.primary`, shown only when `state.hasUnread == true`. Tapping dispatches `NotificationHistoryAction.OnMarkAllRead`.

**States:**

| State | Condition | Rendering |
|-------|-----------|-----------|
| Loading | `state.isLoading && state.items.isEmpty()` | Centered `CircularProgressIndicator` (M3) |
| Empty | `!state.isLoading && state.items.isEmpty()` | EmptyNotifications composable (see below) |
| Error | `state.errorMessage != null` | Snackbar with error message; list still shown if non-empty |
| Populated | `state.items.isNotEmpty()` | `LazyColumn` of `NotificationRow` cards |

**Loading state:** `Box(fillMaxSize, contentAlignment = Center) { CircularProgressIndicator() }`. Same pattern as LoadingPlaceholder in CustomerOrderHistoryScreen but using the M3 indicator instead of text (prefer indicator for async loads).

**Empty state composable (`EmptyNotifications`):**
```
Column(fillMaxSize, padding = 32 dp, verticalArrangement = Center, horizontalAlignment = Center) {
  Icon(Icons.Default.Notifications, size = 48 dp, tint = colorScheme.onSurfaceVariant, contentDescription = null)
  Spacer(16 dp)
  Text("No notifications yet", titleMedium)
  Spacer(8 dp)
  Text("Order updates and alerts will appear here.", bodyMedium, onSurfaceVariant)
}
```

**Populated state — `LazyColumn`:**
- `contentPadding = PaddingValues(16 dp)`
- `verticalArrangement = Arrangement.spacedBy(8 dp)`
- Items keyed by `item.id`

**Notification row card (`NotificationRow`):**
```
Card(
  modifier = fillMaxWidth + clickable { onItemClick(item) },
  elevation = CardDefaults.cardElevation(defaultElevation = 2 dp),
  colors = if (item.isRead)
    CardDefaults.cardColors()  // default surface
  else
    CardDefaults.cardColors(containerColor = colorScheme.primaryContainer.copy(alpha = 0.15f))
) {
  Row(modifier = padding(16 dp), verticalAlignment = CenterVertically) {

    // Unread dot (leading)
    if (!item.isRead) {
      Box(modifier = size(8 dp) + background(colorScheme.primary, CircleShape))
      Spacer(4 dp)
    } else {
      Spacer(12 dp)  // same total width to keep icon aligned
    }

    // Type icon
    Icon(
      imageVector = typeIcon(item.type),  // from type vocabulary table
      contentDescription = typeContentDescription(item.type),
      tint = typeIconTint(item.type),
      modifier = size(24 dp)
    )

    Spacer(12 dp)

    // Text block
    Column(modifier = weight(1f), verticalArrangement = spacedBy(4 dp)) {
      Text(
        text = item.title,
        style = if (item.isRead) titleSmall.copy(fontWeight = Normal) else titleSmall,
        maxLines = 1,
        overflow = Ellipsis
      )
      Text(
        text = item.body,
        style = bodyMedium,
        color = colorScheme.onSurfaceVariant,
        maxLines = 2,
        overflow = Ellipsis
      )
      Text(
        text = relativeTimestamp(item.createdAt),  // e.g. "2 min ago", "Yesterday"
        style = bodySmall,
        color = colorScheme.onSurfaceVariant
      )
    }

    // Chevron
    Icon(
      Icons.Default.ChevronRight,
      contentDescription = null,
      tint = colorScheme.onSurfaceVariant
    )
  }
}
```

**Tap interaction:** `onItemClick(item)` → ViewModel dispatches mark-read + navigates to deep-link destination based on `item.type` and payload (orderId / sellerOrderId / productId+productTitle). The navigation call happens in the screen's `LaunchedEffect` consuming a one-shot `effect` from the ViewModel (same pattern as the existing deep-link LaunchedEffect in MainActivity).

**Pull-to-refresh:** Wrap `LazyColumn` (and loading/empty placeholders) in `PullToRefreshBox` (M3 `ExperimentalMaterial3Api`). Matches CustomerOrderHistoryScreen. State field: `state.isRefreshing`. Action: `NotificationHistoryAction.OnRefresh`.

### 2. Unread Count Badge — Entry Point

**Decision (Claude's discretion, D-01b):** Include a basic unread badge. Rationale: Room already tracks `read` flag; a `BadgedBox` wrapping the navigation item costs one `collectAsStateWithLifecycle` call in the tab host.

**Customer bottom nav entry:**
- Add a "Notifications" item to `CustomerTabs` between Wishlist and Profile:
  `Notifications(text = R.string.notifications, selectedIcon = Icons.Filled.Notifications, unselectedIcon = Icons.Outlined.Notifications)`
- Wrap the `NavigationBarItem` icon in `BadgedBox`:
  ```
  BadgedBox(badge = { if (unreadCount > 0) Badge { Text(unreadCount.toString()) } }) {
    Icon(...)
  }
  ```
- Badge uses M3 `Badge` with `containerColor = colorScheme.error` (system convention for count badges).
- Cap displayed count: show "9+" when unreadCount > 9.
- `unreadCount` sourced from `NotificationHistoryViewModel.unreadCount: StateFlow<Int>` (or a lightweight shared `NotificationBadgeViewModel`), observed in the tab host composable.

**Seller bottom nav entry:**
- Add "Notifications" to `SellerTabs` between Discounts and Profile using the same icon + BadgedBox pattern.

**Alternative deep-entry from Profile screen (belt-and-suspenders):**
- `CustomerProfileScreen` and `SellerProfileScreen` already contain a menu-item list. Add a `ProfileMenuItem(icon = Icons.Default.Notifications, title = "Notifications", subtitle = "View notification history")` row. This navigates to the same `NotificationHistoryScreen` route and does NOT show a badge (the bottom-nav badge is sufficient).

### 3. POST_NOTIFICATIONS Rationale Dialog (`NotificationPermissionRationaleDialog`)

**Trigger:** Shown once after login, on first composition of the authenticated home screen (Customer or Seller), gated by: `isFirstLaunchAfterLogin && !hasRequestedPermission && Build.VERSION.SDK_INT >= 33`. Stored in `NotificationPreferences` (DataStore — already exists at `data/repository/NotificationPreferences.kt`).

**Component:** `AlertDialog` (M3).

```
AlertDialog(
  onDismissRequest = { onDismiss() },
  icon = { Icon(Icons.Default.Notifications, contentDescription = null, tint = colorScheme.primary) },
  title = { Text("Stay in the loop") },
  text = {
    Text(
      "Get notified when your orders ship, when customers place new orders, " +
      "and when reviews come in — right on your device."
    )
  },
  confirmButton = {
    Button(onClick = { onEnable() }) { Text("Enable") }
  },
  dismissButton = {
    TextButton(onClick = { onDismiss() }) { Text("Not now") }
  }
)
```

**"Enable" action:** Dismisses the dialog, then launches `ActivityResultContracts.RequestPermission(Manifest.permission.POST_NOTIFICATIONS)`. No Accompanist dependency — use `rememberLauncherForActivityResult` directly.

**"Not now" action:** Dismisses the dialog. Sets `hasRequestedPermission = true` in DataStore so the dialog does not re-appear on subsequent launches. Does NOT retry automatically.

**Accessibility:** Dialog is announced by TalkBack as a dialog (`AlertDialog` handles this). Icon has `contentDescription = null` (decorative; title conveys meaning).

### 4. "Enable Notifications" Settings Affordance

**Location — Customer:** `CustomerProfileScreen` → existing "Settings" `ProfileMenuItem` row is a stub. Add a new `ProfileMenuItem` specifically for notifications above it:
```
ProfileMenuItem(
  icon = Icons.Default.Notifications,
  title = "Notifications",
  subtitle = if (notificationsEnabled) "Notifications are on" else "Tap to enable notifications",
  textColor = if (!notificationsEnabled) colorScheme.error else colorScheme.onSurface
)
```
Tap action when permission denied: `Intent(Settings.ACTION_APP_NOTIFICATION_SETTINGS)` with `EXTRA_APP_PACKAGE = context.packageName` → `startActivity`. When permission is granted, tapping navigates to the NotificationHistoryScreen instead (or the row is styled as a passive info row).

**Location — Seller:** Same row added to the "Settings" `Card` in `SellerProfileScreen`, using the existing `SettingsItem` composable:
```
SettingsItem(
  icon = Icons.Default.Notifications,
  title = "Notifications",
  subtitle = if (notificationsEnabled) "Notifications are on" else "Tap to enable notifications",
  onClick = { /* open system settings or history */ }
)
```

**Permission state detection:** `ContextCompat.checkSelfPermission(context, POST_NOTIFICATIONS) == PERMISSION_GRANTED` (API 33+; always true pre-33). Observe in a `produceState` or ViewModel field that re-checks `onResume` (via `Lifecycle.Event.ON_RESUME` effect).

**Icon:** `Icons.Default.Notifications` with `colorScheme.primary` tint when enabled, `colorScheme.error` tint when disabled — mirrors the red "Sign Out" pattern in `CustomerProfileScreen` for attention-requiring states.

## Interaction Contracts

### Notification Row Tap
1. User taps a `NotificationRow` card.
2. `NotificationHistoryAction.OnItemClick(item)` dispatched to ViewModel.
3. ViewModel: if `!item.isRead`, write `read = true` to Room (optimistic) + queue Firestore update.
4. ViewModel emits a one-shot navigation effect: `NavigateToDestination(target, payload)`.
5. Screen's `LaunchedEffect(effect)` calls the appropriate nav callback (`onNavigateToOrderDetail(orderId)`, `onNavigateToSellerOrder(sellerOrderId)`, `onNavigateToProductReviews(productId, productTitle)`).
6. Back-navigation returns the user to the notification history screen (not popped).

### Mark All Read
1. User taps "Mark all read" TextButton in TopAppBar.
2. `NotificationHistoryAction.OnMarkAllRead` dispatched.
3. ViewModel: bulk-update all `read = false` items in Room to `read = true`; queue Firestore batch write.
4. TopAppBar action disappears immediately (state update: `hasUnread = false`).

### Pull to Refresh
1. User pulls down on the `PullToRefreshBox`.
2. `NotificationHistoryAction.OnRefresh` dispatched.
3. ViewModel sets `isRefreshing = true`, triggers a Firestore re-sync to Room, then sets `isRefreshing = false`.

### Permission Rationale Dialog — Enable
1. Dialog shown once on first authenticated home composition (API 33+).
2. User taps "Enable" → dialog dismissed → `ActivityResultContracts.RequestPermission` launcher invoked for `POST_NOTIFICATIONS`.
3. On grant: FCM token refresh triggered (WorkManager job enqueued per D-05). DataStore `hasRequestedPermission = true`.
4. On deny: DataStore `hasRequestedPermission = true`, `wasPermissionDenied = true`. No re-prompt.

### Permission Rationale Dialog — Not Now
1. User taps "Not now" → dialog dismissed.
2. DataStore `hasRequestedPermission = true`. No system dialog shown.
3. Profile screen "Notifications" row shown with "Tap to enable notifications" subtitle.

### Settings Row → System Settings
1. User taps "Notifications" row when permission is denied.
2. `Intent(Settings.ACTION_APP_NOTIFICATION_SETTINGS, extras = EXTRA_APP_PACKAGE)` launched.
3. Android system Notification Settings screen opens.
4. On return (`Lifecycle.ON_RESUME`): permission state re-checked; row subtitle updates if now granted.

## Accessibility

| Element | Requirement |
|---------|-------------|
| Type icon in notification row | `contentDescription` = type-specific string from type vocabulary table (never null) |
| Unread dot | Not focusable as a standalone element; unread state communicated via `semantics { contentDescription = "Unread: ${item.title}" }` on the row Card |
| Mark all read button | Default Button semantics; no extra annotation needed |
| BadgedBox unread badge | M3 Badge announces count automatically via semantics |
| Rationale dialog | `AlertDialog` — TalkBack reads title + body + button labels automatically |
| Settings intent row | `contentDescription` on Icon = "Notifications"; row uses `clickable` with `role = Role.Button` |
| Empty state icon | `contentDescription = null` (decorative; heading communicates meaning) |
| Loading indicator | Add `semantics { contentDescription = "Loading notifications" }` on `CircularProgressIndicator` container |
| Relative timestamps | Full ISO timestamp as tooltip/`semantics.stateDescription` for screen-reader users: `stateDescription = item.createdAt.toFormattedDateTime()` |
| Minimum touch target | All tappable rows render at minimum 48 dp height (Card with 16 dp vertical padding + two text lines satisfies this) |

- Status: READY FOR CHECKER

### Dimension 6 — Registry Safety
