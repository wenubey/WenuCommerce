<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Android client → Firestore | Authenticated client writes/deletes follow docs under its own space |
| Firestore → Cloud Function (Admin SDK) | Trigger runs with Admin privileges; the ONLY writer of `followerCount` |
| Seller (any authenticated user) → another user's follow subcollection | Must be denied (FAVS-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05 | Tampering | Client writing `followerCount` on a USERS doc directly | mitigate | The counter is maintained ONLY by the Admin-SDK trigger. The client never writes it (enforced in 09-01 repo). NOTE: the broad `allow write: if auth != null` on USERS still technically permits a crafted client write to `followerCount` — this residual is documented follow-up debt (Open Question 2), out of Phase 9 scope; the app itself never issues such a write. |
| T-09-06 | Info Disclosure | Seller enumerating who follows them | mitigate | Structural: follow docs live under `USERS/{customerId}/followed_sellers/...`; rule `request.auth.uid == userId` blocks any cross-user read/list. The seller only ever reads the aggregate `followerCount` on their own USERS doc (FAVS-04). |
| T-09-07 | Tampering | Double-follow / unfollow-when-not-following counter drift | mitigate | `wasFollowing === isNowFollowing` no-op guard in the trigger; fixed-path follow doc = upsert (not append). Client-side LOADING-disabled button (09-03) is the primary guard; the trigger guard is the safety net. |
| T-09-08 | Denial of Service | update() on a deleted seller's USERS doc throwing NOT_FOUND | mitigate | Use `set(..., {merge: true})` not `update()` (Pitfall 4); the write is wrapped in try/catch and never throws, so a missing seller doc cannot crash the function. |
| T-09-SC | Tampering (supply chain) | npm installs in functions/ | mitigate | No new npm packages added (09-RESEARCH.md Package Legitimacy Audit: none — firebase-functions/admin already present). No install task; no `[ASSUMED]`/`[SUS]` package to gate. |
</threat_model>
