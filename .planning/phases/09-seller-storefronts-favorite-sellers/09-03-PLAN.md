## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User (possibly signed-out) → Follow action | Untrusted intent to mutate follow state crosses into the ViewModel |
| ViewModel → FollowedSellersRepository | Auth-verified userId + sellerId cross into the data layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-09 | Elevation | Signed-out customer tapping Follow | mitigate | ViewModel.onFollow guards `userId.isNullOrBlank()` → shows the auth-gate AlertDialog and makes NO repo call / no Room write (D-03). Verified by the onFollow_withoutAuth test. |
| T-09-10 | Tampering | Self-follow count inflation | mitigate | ViewModel compares `authRepository.currentUser.value?.uuid == sellerId`; on match followState = HIDDEN (no button rendered) and onFollow is a no-op (Pitfall 2). Verified by the onFollow_selfSellerId test. |
| T-09-11 | Tampering | Double-follow via rapid re-tap (counter drift) | mitigate | followState → LOADING immediately on tap; FollowButton LOADING state is disabled, blocking a second write during the async window (Pitfall 1). Server-side no-op guard (09-02) is the safety net. |
| T-09-12 | Spoofing / Input Validation | sellerId from savedStateHandle / product used in a Firestore path | mitigate | ViewModel treats a null/blank sellerId as a no-op (existing stub behavior at line 29); onFollow requires a non-blank sellerId before calling the repository (V5 input validation — empty path segments are rejected by Firestore anyway). |
| T-09-SC | Tampering (supply chain) | dependency installs | mitigate | No new libraries (09-UI-SPEC Registry Safety + 09-RESEARCH Package Audit: none). No install task. |
</threat_model>
