## Spacing Scale

Declared values (multiples of 4 dp — matches 8-point grid at Compose dp):

| Token | Value | Usage in this phase                                                       |
|-------|-------|---------------------------------------------------------------------------|
| xs    | 4 dp  | Icon-to-text gaps, star icon gaps, meta-row inline padding, inner Column gap in FollowedSellerRow |
| sm    | 8 dp  | Between header sub-rows, between product card items in the grid           |
| md    | 16 dp | Card internal padding, screen horizontal padding, header card padding, LazyColumn item spacing |
| lg    | 24 dp | Empty-state icon bottom margin, follower-count stat label margin          |
| xl    | 32 dp | Empty-state column outer padding (matches WishlistEmptyState pattern)     |
| 2xl   | 48 dp | Not used in primary layouts this phase                                    |
| 3xl   | 64 dp | Not used in primary layouts this phase                                    |

Exceptions:
- Seller photo in storefront header: 72 dp diameter (CircleShape — matches SellerProfileScreen's 80 dp avatar, scaled slightly for a card-embedded context).
- Seller photo in Followed Sellers list row: 48 dp diameter (CircleShape — matches ProfileMenuItem icon sizing convention).
- Follow/Unfollow button minimum touch target: 48 dp tall (Android accessibility minimum).
- Star icon size in aggregate rating row: 16 dp (matches existing product-card star convention from CustomerProductCard).
- Type icon size for stat cards: 28 dp (matches SellerDashboardScreen SellerStatsCard convention).

Source: Inferred from CustomerProductCard (16 dp card padding, 4 dp icon-text gap), SellerProfileScreen (80 dp avatar, 16 dp padding), WishlistEmptyState (32 dp outer padding), Phase 08 UI-SPEC.

## Color

The project uses dynamic color (system-generated scheme on API 31+) with a fixed fallback.
All surface/accent values are M3 colorScheme tokens, not hardcoded hex.
(The Phase 08 code review flagged hardcoded ARGB as a defect — this contract prohibits them.)

| Role               | M3 Token                              | Specific usage in this phase                                           |
|--------------------|---------------------------------------|------------------------------------------------------------------------|
| Dominant (60%)     | `colorScheme.background` / `.surface` | Screen backgrounds, Scaffold content area                              |
| Secondary (30%)    | `colorScheme.surfaceVariant`          | Business header card container, Followed Sellers row card container    |
| Accent (10%)       | `colorScheme.primary`                 | Follow button (filled), seller-name tap target text color, follower count stat value, page indicator active dot |
| Destructive        | `colorScheme.error`                   | Unfollow confirmation text, error snackbar, logged-out auth-gate copy  |

Accent reserved for (explicit list):
1. Follow button container color when active (filled `Button` with `colorScheme.primary`).
2. Seller-name text in product card and product detail — `colorScheme.primary` to signal tappability (D-01).
3. Follower count numeric value on seller dashboard / seller profile stat card (`colorScheme.primary`).
4. Star rating fill color: `Color(0xFFFFC107)` — amber, matches existing codebase in CustomerProductCard and CustomerProductDetailScreen. This single hardcoded value is consistent with prior phases and is the established project convention for star icons; do not substitute a colorScheme token.
5. Active pager dot in storefront product images (inherited from CustomerProductDetailScreen).

Unfollow button: `OutlinedButton` (no filled container) with `colorScheme.error` text and border — signals a reversible but attention-requiring action, consistent with the existing Sign-Out red pattern in CustomerProfileScreen.

Auth-gate `AlertDialog` for unauthenticated Follow tap: standard M3 AlertDialog colors (no overrides).

## Surface Specifications

### 1. Seller Storefront Screen (`SellerStorefrontScreen`)

**Route:** Existing `SellerStorefront(sellerId: String)` route in `AppNavigationObjects.kt`. Extension of the current stub (D-05 — build on, do not recreate).

**Scaffold structure:**
```
Scaffold(
  topBar = TopAppBar(
    title = Text(state.sellerName.ifBlank { "Seller Store" }, titleLarge),
    navigationIcon = Icons.AutoMirrored.Filled.ArrowBack, contentDescription = "Back"
  ),
  snackbarHost = SnackbarHost
)
```

TopAppBar receives `onNavigateBack` callback → `navController.navigateUp()` (missing from current stub; add this parameter).

**Content structure — single `LazyColumn` wrapping everything (CD-05):**
```
LazyColumn(
  modifier = fillMaxSize,
  contentPadding = PaddingValues(horizontal = 16 dp, vertical = 8 dp),
  verticalArrangement = spacedBy(16 dp)
) {
  item { StorefrontHeaderCard(...) }   // always item 0
  item { "Products" section heading }  // only when populated
  items(state.products, key = { it.id }) { CustomerProductCard(...) }
  // OR: item { StorefrontEmptyProductsState() }
  // OR: item { CircularProgressIndicator() } when loading
}
```

Wrap the entire `LazyColumn` (plus loading placeholder) in `PullToRefreshBox` (M3 `ExperimentalMaterial3Api`). `state.isRefreshing` drives the indicator; `StorefrontAction.OnRefresh` reloads seller info + products.

**State machine:**

| State | Condition | Rendering |
|-------|-----------|-----------|
| Loading | `state.isLoading && state.products.isEmpty()` | `Box(fillMaxSize) { CircularProgressIndicator() }` — full-screen centered; no header yet |
| Error | `state.errorMessage != null && state.products.isEmpty()` | `Box(fillMaxSize) { Text(error, colorScheme.error) }` |
| Empty products | `!state.isLoading && state.products.isEmpty() && state.seller != null` | Header card shown; below it `StorefrontEmptyProductsState` |
| Populated | `state.products.isNotEmpty()` | Header card + "Products" label + product list |

#### 1a. Business Header Card (`StorefrontHeaderCard`)

The first `LazyColumn` item. A `Card` with `fillMaxWidth`, elevation 4 dp, internal padding 16 dp.

```
Card(elevation = 4 dp, modifier = fillMaxWidth) {
  Column(padding = 16 dp, verticalArrangement = spacedBy(16 dp)) {

    // Row 1: Photo + name + meta
    Row(verticalAlignment = CenterVertically, horizontalArrangement = spacedBy(16 dp)) {
      AsyncImage(
        model = seller.profilePhotoUri,  // User.profilePhotoUri (D-02)
        modifier = size(72 dp) + clip(CircleShape),
        contentScale = Crop,
        contentDescription = "${seller.businessName} seller photo"
      )
      // Fallback when profilePhotoUri is null/blank:
      // Box(size(72dp), CircleShape, containerColor = colorScheme.surfaceVariant) {
      //   Icon(Icons.Default.Store, size=36dp, tint=colorScheme.onSurfaceVariant)
      // }

      Column(verticalArrangement = spacedBy(4 dp)) {
        Text(seller.businessName, titleLarge, fontWeight = Bold)

        // Aggregate rating row (CD-04) — shown only when reviewCount > 0
        if (seller.reviewCount > 0) {
          Row(verticalAlignment = CenterVertically) {
            Icon(Icons.Filled.Star, size=16dp, tint=Color(0xFFFFC107), contentDescription=null)
            Spacer(4 dp)
            Text("%.1f (%d reviews)".format(seller.averageRating, seller.reviewCount),
                 bodySmall)
          }
        }

        // Follower count row
        Row(verticalAlignment = CenterVertically) {
          Icon(Icons.Default.Group, size=16dp, tint=colorScheme.onSurfaceVariant,
               contentDescription=null)
          Spacer(4 dp)
          Text(formatFollowerCount(seller.followerCount), bodySmall,
               color=colorScheme.onSurfaceVariant)
        }
      }
    }

    // Row 2: Bio — shown only when businessDescription is not blank (D-02)
    if (seller.businessDescription.isNotBlank()) {
      Text(seller.businessDescription, bodyMedium, maxLines=4, overflow=Ellipsis)
    }

    // Row 3: Follow / Unfollow button
    FollowButton(
      followState = state.followState,
      onFollow = { dispatch(StorefrontAction.OnFollow) },
      onUnfollow = { dispatch(StorefrontAction.OnUnfollow) },
      modifier = fillMaxWidth
    )
  }
}
```

**Follower count format function** `formatFollowerCount(count: Int): String`:
- 0–999 → display as plain number: `"0"`, `"1"`, `"999"`
- 1,000–9,999 → one decimal: `"1.2k"`, `"9.9k"`
- 10,000–999,999 → round to nearest hundred, no decimal: `"10k"`, `"145k"`
- 1,000,000+ → one decimal with M: `"1.2M"`

Zero state text when followerCount == 0: display `"0"` (not hidden — the count being 0 is valid information).

#### 1b. Follow Button (`FollowButton`)

A standalone reusable composable (analogous to `WishlistHeartButton`). Location: `core/components/FollowButton.kt`.

Visual states:

| State | Component | Appearance | Label |
|-------|-----------|------------|-------|
| NOT_FOLLOWING | `Button` (filled) | `colorScheme.primary` container | "Follow" |
| FOLLOWING | `OutlinedButton` | `colorScheme.error` text + border | "Unfollow" |
| LOADING | `Button` (filled, disabled) | `colorScheme.primary` container, disabled alpha | `CircularProgressIndicator(size=16dp, strokeWidth=2dp)` in place of label |
| LOGGED_OUT | `Button` (filled) | `colorScheme.primary` container | "Follow" — tapping → sign-in gate (D-03) |

Scale-bounce animation on follow-state toggle (same `Animatable` pattern as `WishlistHeartButton`): animate to 1.1f then back to 1.0f with `spring(dampingRatio = Spring.DampingRatioMediumBouncy)`. Applied to the button content, not the button container.

**Optimistic toggle (FAVS-01):**
1. Customer taps "Follow": state immediately transitions LOADING → FOLLOWING (optimistic).
2. ViewModel writes to Room + Firestore async.
3. On Firestore failure: revert state to NOT_FOLLOWING + show snackbar "Couldn't follow. Try again."
4. Customer taps "Unfollow": state immediately transitions LOADING → NOT_FOLLOWING (optimistic).
5. On Firestore failure: revert state to FOLLOWING + show snackbar "Couldn't unfollow. Try again."

**Logged-out tap (D-03):**
Customer taps "Follow" without being signed in → `AlertDialog` (existing pattern from `CustomerProductDetailScreen.showLoginPrompt`):
```
AlertDialog(
  title = { Text("Sign in required") },
  text = { Text("Sign in to follow this seller and get updates.") },
  confirmButton = { TextButton("Sign In") { onNavigateToSignIn() } },
  dismissButton = { TextButton("Not Now") { dismiss() } }
)
```
The Follow button does NOT persist an anonymous follow. No Room write for logged-out users (D-03).

#### 1c. Product Grid (storefront product listing)

Reuses `CustomerProductCard` unchanged. The seller-name in each card becomes the storefront tap target (D-01 — handled by the card modification in section 6 below, not by this screen).

Layout within the `LazyColumn`:
- Section heading: `Text("Products", titleMedium, padding(vertical=8dp))`
- One column (`LazyColumn` items), full-width cards, 16 dp vertical spacing (matches the declared `md` token and the outer `LazyColumn` `verticalArrangement = spacedBy(16.dp)`).
- Rationale for single-column (not 2-column grid): `CustomerProductCard` is a wide horizontal card design (image left, text right — 80 dp image + text column); a 2-column grid would require a redesigned compact card. Using the existing card unchanged honors D-05 (extend, do not rewrite) and avoids a new composable.

**Empty products state (`StorefrontEmptyProductsState`):**
```
Box(fillMaxWidth, padding=32dp, contentAlignment=Center) {
  Column(horizontalAlignment=CenterHorizontally, verticalArrangement=spacedBy(8dp)) {
    Icon(Icons.Default.Inventory, size=48dp, tint=colorScheme.onSurfaceVariant,
         contentDescription=null)
    Text("No active products", titleMedium)
    Text("This seller hasn't listed any products yet.", bodyMedium,
         color=colorScheme.onSurfaceVariant, textAlign=Center)
  }
}
```

**Error state:** Snackbar (via `SnackbarHost`) with message "Couldn't load products. Pull down to retry." The header card (if seller info loaded successfully) remains visible so the Follow button is still accessible.

**Route:** New type-safe `FollowedSellers` route in `AppNavigationObjects.kt` + `TabNavRoutes.kt` (same pattern as `NotificationHistory` — standalone `composable<FollowedSellers> { FollowedSellersScreen(...) }`).

**Scaffold structure:**
```
Scaffold(
  topBar = TopAppBar(
    title = Text("Followed Sellers", titleLarge),
    navigationIcon = Icons.AutoMirrored.Filled.ArrowBack, contentDescription = "Back"
  ),
  snackbarHost = SnackbarHost
)
```

**States:**

| State | Condition | Rendering |
|-------|-----------|-----------|
| Loading | `state.isLoading && state.sellers.isEmpty()` | Centered `CircularProgressIndicator` |
| Empty | `!state.isLoading && state.sellers.isEmpty()` | `FollowedSellersEmptyState` composable |
| Error | `state.errorMessage != null` | Snackbar + list still shown if non-empty |
| Populated | `state.sellers.isNotEmpty()` | `LazyColumn` of `FollowedSellerRow` cards |

**Populated state — `LazyColumn`:**
- `contentPadding = PaddingValues(16 dp)`
- `verticalArrangement = Arrangement.spacedBy(8 dp)`
- Items keyed by `item.sellerId`

**Followed Seller row card (`FollowedSellerRow`):**
```
Card(
  modifier = fillMaxWidth + clickable { onSellerClick(item.sellerId) },
  elevation = CardDefaults.cardElevation(defaultElevation = 2 dp)
) {
  Row(modifier = padding(16 dp), verticalAlignment = CenterVertically,
      horizontalArrangement = spacedBy(16 dp)) {

    // Seller photo
    AsyncImage(
      model = item.sellerLogoUrl,
      modifier = size(48 dp) + clip(CircleShape),
      contentDescription = "${item.sellerName} seller photo",
      contentScale = Crop
    )
    // Fallback: Box(48dp, CircleShape, surfaceVariant) { Icon(Store, 24dp) }

    // Text block
    Column(modifier = weight(1f), verticalArrangement = spacedBy(4 dp)) {
      Text(item.sellerName, titleSmall, fontWeight=SemiBold, maxLines=1, overflow=Ellipsis)
      Text("Followed", bodySmall, color=colorScheme.onSurfaceVariant)
    }

    // Unfollow button
    OutlinedButton(
      onClick = { dispatch(FollowedSellersAction.OnUnfollow(item.sellerId)) },
      colors = ButtonDefaults.outlinedButtonColors(contentColor = colorScheme.error),
      border = BorderStroke(1.dp, colorScheme.error)
    ) {
      Text("Unfollow", labelLarge)
    }

    // Chevron (tap row → storefront)
    Icon(Icons.Default.ChevronRight, contentDescription = null,
         tint = colorScheme.onSurfaceVariant)
  }
}
```

**Unfollow from this screen (optimistic, no undo):**
1. Customer taps "Unfollow" → row is removed from list immediately (optimistic Room delete).
2. Firestore write queued async (fire-and-forget per CD-02).
3. On Firestore failure: snackbar "Couldn't unfollow. Try again." + item re-appears.
4. No "Undo" snackbar (unlike wishlist remove-undo pattern) — the Follow button on the storefront provides a natural re-follow path. Keeping it simpler avoids re-adding the item while Firestore is still failing.

**Row tap:** navigates to `SellerStorefront(sellerId = item.sellerId)`.

**Empty state (`FollowedSellersEmptyState`):**
```
Box(fillMaxSize, padding=32dp, contentAlignment=Center) {
  Column(horizontalAlignment=CenterHorizontally, verticalArrangement=spacedBy(16dp)) {
    Icon(Icons.Outlined.FavoriteBorder, size=80dp,
         tint=colorScheme.onSurfaceVariant.copy(alpha=0.5f), contentDescription=null)
    Text("No followed sellers yet", titleLarge, fontWeight=Medium)
    Text("Tap a seller's name on any product to visit their storefront and follow them.",
         bodyMedium, color=colorScheme.onSurfaceVariant, textAlign=Center)
  }
}
```
(Mirrors `WishlistEmptyState` structure — same icon size/alpha, same text pattern, no CTA button since there is no direct "browse sellers" destination.)

### 5. Seller-Name Tap Target on Product Card + Product Detail (D-01)

**Goal:** The seller name in `CustomerProductCard` and in `CustomerProductDetailScreen` becomes a tappable text that navigates to `SellerStorefront(sellerId)`. No separate "Visit Store" button. No avatar-chip.

#### 5a. CustomerProductCard (in `CustomerHomeScreen.kt`)

Current code:
```kotlin
Text(
    text = product.sellerName,
    style = MaterialTheme.typography.labelSmall,
    color = MaterialTheme.colorScheme.onSurfaceVariant,
)
```

Change to:
```kotlin
Text(
    text = product.sellerName,
    style = MaterialTheme.typography.bodySmall,
    color = MaterialTheme.colorScheme.primary,             // accent color signals tappability
    textDecoration = TextDecoration.Underline,              // secondary affordance
    modifier = Modifier
        .clickable { onSellerClick(product.sellerId) }
        .semantics {
            contentDescription = "View ${product.sellerName}'s store"
            role = Role.Button
        }
)
```

`onSellerClick: (sellerId: String) -> Unit` is a new parameter added to `CustomerProductCard`. Thread it from `CustomerHomeScreen` → `CustomerHomeViewModel` → `CustomerHomeAction.OnSellerClick(sellerId)` → navigation callback.

#### 5b. CustomerProductDetailScreen (in `customer_products/CustomerProductDetailScreen.kt`)

Current code:
```kotlin
Text(
    text = "Sold by ${product.sellerName}",
    style = MaterialTheme.typography.bodyMedium,
    color = MaterialTheme.colorScheme.onSurfaceVariant,
)
```

Change to:
```kotlin
Row(verticalAlignment = Alignment.CenterVertically) {
    Text(
        text = "Sold by ",
        style = MaterialTheme.typography.bodyMedium,
        color = MaterialTheme.colorScheme.onSurfaceVariant,
    )
    Text(
        text = product.sellerName,
        style = MaterialTheme.typography.bodyMedium,
        color = MaterialTheme.colorScheme.primary,
        textDecoration = TextDecoration.Underline,
        modifier = Modifier
            .clickable { onSellerClick(product.sellerId) }
            .semantics {
                contentDescription = "View ${product.sellerName}'s store"
                role = Role.Button
            }
    )
}
```

`onSellerClick: (sellerId: String) -> Unit` is a new parameter added to `CustomerProductDetailScreen`. Thread from the navigation host.

**Affordance rationale:** Using `colorScheme.primary` + underline is the minimal change that signals tappability consistently with M3 link conventions, without adding a new button or chip that changes the card's visual weight. No Icon is added (keeps the card compact).

## Interaction Contracts

### Seller Name Tap (D-01)
1. Customer taps the seller name text on `CustomerProductCard` or product detail "Sold by {seller}" link.
2. `onSellerClick(product.sellerId)` callback fires.
3. Navigation: `navController.navigate(SellerStorefront(sellerId = product.sellerId))`.
4. `SellerStorefrontScreen` loads with `isLoading = true` + `CircularProgressIndicator`.
5. Back navigation returns to the originating screen.

### Follow (FAVS-01) — Authenticated
1. Customer taps "Follow" button on storefront header.
2. `StorefrontAction.OnFollow` dispatched.
3. ViewModel: `followState → LOADING` immediately.
4. Optimistic: `followState → FOLLOWING`, `followerCount += 1` on state (not blocking).
5. Room `followed_sellers` insert + Firestore subcollection write async.
6. On success: no snackbar. Follow button shows "Unfollow" state with bounce animation.
7. On failure: `followState → NOT_FOLLOWING`, `followerCount -= 1`; snackbar "Couldn't follow. Try again."

### Unfollow (FAVS-01) — From Storefront
1. Customer taps "Unfollow" button on storefront header.
2. `StorefrontAction.OnUnfollow` dispatched.
3. Optimistic: `followState → NOT_FOLLOWING`, `followerCount -= 1`.
4. Room delete + Firestore subcollection delete async.
5. On success: no snackbar.
6. On failure: `followState → FOLLOWING`, `followerCount += 1`; snackbar "Couldn't unfollow. Try again."

### Follow — Unauthenticated (D-03)
1. Logged-out customer taps "Follow" (button visible, same appearance as authenticated).
2. ViewModel detects `currentUser == null` (or `userId.isBlank()`).
3. Auth-gate `AlertDialog` shown immediately. No Room write, no optimistic state change.
4. Customer taps "Sign In" → navigate to sign-in screen. Customer taps "Not Now" → dialog dismissed, follow button remains in NOT_FOLLOWING state.

### Navigate to Followed Sellers List (D-04)
1. Customer taps "Followed Sellers" row in `CustomerProfileScreen`.
2. `onNavigateToFollowedSellers()` callback fires.
3. Navigation: `navController.navigate(FollowedSellers)`.
4. `FollowedSellersScreen` loads list from Room (fast offline path) + triggers background Firestore sync.

### Unfollow from Followed Sellers List
1. Customer taps "Unfollow" button on a `FollowedSellerRow`.
2. `FollowedSellersAction.OnUnfollow(sellerId)` dispatched.
3. Optimistic: row removed from `state.sellers` list immediately (Room delete + list update).
4. Firestore subcollection delete async (fire-and-forget).
5. On failure: row re-appears at its original position; snackbar "Couldn't unfollow. Try again."

### Row Tap in Followed Sellers List
1. Customer taps a `FollowedSellerRow` card body (not the Unfollow button).
2. Navigate to `SellerStorefront(sellerId = item.sellerId)`.

### Pull to Refresh — Storefront
1. Customer pulls down `PullToRefreshBox`.
2. `StorefrontAction.OnRefresh` dispatched.
3. `isRefreshing = true`; re-fetches seller info + products from Firestore.
4. On complete: `isRefreshing = false`. Snackbar on error.

### Pull to Refresh — Followed Sellers
1. Customer pulls down `PullToRefreshBox` on `FollowedSellersScreen`.
2. `FollowedSellersAction.OnRefresh` dispatched.
3. Re-syncs Room from Firestore; updates list.
